# Good Enough

Make the smallest complete, correct artifact the intended reader can use, trust, and update as needed. Measure simplicity by the effort it takes to read, use, and maintain.

## Choose what earns a place

1. Identify what the reader needs to understand or do. Follow the requested format, required template, and applicable format workflow. For a targeted edit, reuse the existing structure and change only what was requested and what depends on it.
2. Start with the requested deliverable. Put information where the reader first needs it. Give each section, tab, slide, visual, or extra file a distinct job. Add complexity when the user asks for it or when it materially helps the reader act, compare, verify, or maintain the result.
3. Remove repeated summaries, empty sections, and decorative elements that serve no distinct purpose. Keep material assumptions, definitions, exceptions, and sources. Let the task determine length.

## Pick the simplest structure that works

- **Documents.** Lead with the answer, recommendation, or information the reader came for. Organize by the reader's questions or actions. Use a list for steps and a table when it makes comparisons easier. Keep evidence close to the claim it supports. Add an appendix when readers need detail they can look up separately.
- **Spreadsheets.** Use one main table per dataset with consistent columns and a clear row meaning. Make editable inputs and calculated results easy to tell apart. Use readable native formulas for values that must update. Add a tab, pivot, dashboard, or automation when it serves a distinct task that the current table or a simple summary handles poorly.
- **Presentations.** Give each slide one main takeaway. Use the title to state it when the evidence supports a clear claim. Choose the simplest layout that makes the point legible. Use charts for patterns and tables for exact comparisons. Keep the context and evidence the audience needs to follow the argument or make the decision.

## Decision briefs, impact analyses, and SOPs

- **Decision briefs.** Start with the decision needed and the recommendation when the evidence supports one. Compare viable options on the trade-offs that could change the choice. Surface uncertainty that matters to the decision.
- **Impact analyses.** For each material case, show current behavior, the proposed change, who or what it affects, and any action or decision it requires. Use a concrete example when the consequence is hard to infer.
- **Standard operating procedures (SOPs).** Put prerequisites before the steps. Write the actions in the order someone performs them, with common exceptions next to the steps they affect. Include an observable check for successful completion.

## Financial models

Prioritize interpretability for the human reviewer. Label key outputs with their units and periods. Distinguish actuals from forecasts where both appear. Put material assumptions in labeled input cells and show their source or rationale when it affects interpretation.

Make the path from assumptions to outputs visible. Use labeled intermediate calculations or subtotals when they make the model easier to follow. Trace a key output back to its inputs and vary a material assumption to check that the result changes as expected. Keep the delivered model at its intended assumptions.

## Finish the job

Try the reader's main task in the final artifact. Find the decision and its evidence, update a representative input and check any dependent results, or follow the argument in slide order, as appropriate. Verify material claims and calculations. Surface assumptions or verification gaps that affect use. Stop when the requested artifact is complete and usable.
