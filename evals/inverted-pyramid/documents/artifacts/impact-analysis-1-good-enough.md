# Return request expiry — launch impact analysis

After launch, in-scope return requests expire after seven calendar days in **Awaiting customer documents**. The clock starts when the request enters that status. Customers will see **Expired** in the portal and can submit a new request. The expired request stays closed.

**Product still needs to decide whether the rule applies to requests already open on launch day.** That decision determines whether Support and Operations should apply the seven-day rule when advising customers about those requests.

| Case | Today | After launch | Team action |
|---|---|---|---|
| Awaiting customer documents | The request stays open indefinitely unless someone closes it. | An in-scope request expires after seven calendar days in this status. | Operations should use the status-entry date to determine how much time remains. |
| Expired request | Open requests have no automatic expiry. | The portal shows **Expired**. The customer can submit a new request, and the expired request stays closed. | Support should explain how to submit a new request. |
| Internal review | The request stays open unless someone closes it. | This status is unaffected by the expiry rule. | Support and Operations can continue their existing handling. |
| Completed or cancelled | The record is already closed. | The record remains untouched. | No action required. |

**Example.** R-82 was created nine days ago and entered **Awaiting customer documents** two days ago. If the request is in scope, it has five calendar days left in that status.

**Expiry email.** Communications still needs to decide whether to send an expiry email. Support can explain what customers will see in the portal while the email decision is pending.
