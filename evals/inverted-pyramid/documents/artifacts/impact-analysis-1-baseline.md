# Return request expiry — launch impact analysis

Return requests will expire after **seven calendar days in Awaiting customer documents**. Today, open requests stay open indefinitely unless someone closes them. The seven-day clock starts when the request enters that status. The creation date does not affect the deadline.

## What changes for customers

- The portal shows **Expired** when the request expires.
- The expired request stays closed. The customer can submit a new return request.
- Requests in **Internal review** are unaffected. Completed and cancelled records remain untouched.

**Example — R-82** was created nine days ago and entered **Awaiting customer documents** two days ago. If the rule applies to R-82, it has **five calendar days left** in that status before it expires.

## Impact by team

| Team | Launch impact |
| --- | --- |
| Support | Explain that the deadline runs from entry into **Awaiting customer documents**. When a customer sees **Expired**, explain how to submit a new return request and that the expired request stays closed. |
| Operations | Use the date the request entered **Awaiting customer documents** to determine when it expires. The launch-day scope decision determines which existing requests are subject to expiry. |
| Product | Decide whether the rule applies to requests already open on launch day. This determines whether requests such as R-82 can expire under the rule. |

## Open launch decisions

| Owner | Decision |
| --- | --- |
| Product | Does the expiry rule apply to requests already open on launch day? |
| Communications | Will customers receive an expiry email? The portal will show **Expired** regardless of the email decision. |
