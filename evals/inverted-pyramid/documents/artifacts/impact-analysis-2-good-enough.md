# Return request expiry — launch impact

After launch, in-scope return requests expire after seven calendar days in **Awaiting customer documents**, counted from when they enter that status. The customer sees **Expired** in the portal and can submit a new request. The expired request stays closed.

**Launch decision for Product:** Decide whether the rule applies to requests already open on launch day. Operations and Support need that decision before they can confirm which existing requests can expire.

| Request status | Today | After launch | Team action |
|---|---|---|---|
| Awaiting customer documents | Stays open indefinitely unless someone closes it. | An in-scope request expires after seven calendar days in this status. | Operations uses the date the request entered the status to determine its expiry. Support explains how to submit a new request if it expires. |
| Internal review | Stays open indefinitely unless someone closes it. | Continues under the same rules. | Operations continues the existing review process. |
| Completed or cancelled | Already closed. | Records remain untouched. | No action needed. |

**Example:** R-82 was created nine days ago and entered **Awaiting customer documents** two days ago. If it is in scope, it has five calendar days left in that status.

**Customer communications:** Communications still needs to decide whether to send an expiry email. Support can tell customers they’ll see **Expired** in the portal.
