# Return request expiry · Launch impact analysis

After launch, an in-scope return request will expire after seven calendar days in **Awaiting customer documents**, counted from when it entered that status. The customer will see **Expired** in the portal and can submit a new request. The expired request stays closed.

**Product’s launch decision:** Will the rule apply to requests already open on launch day? Until Product decides, Support and Operations should treat expiry timing for those requests as conditional.

| Request status | Current behavior | After launch |
| --- | --- | --- |
| Awaiting customer documents | Stays open indefinitely unless someone closes it. | Expires after seven calendar days in that status if the request is in scope. The clock starts at status entry. |
| Internal review | Stays open indefinitely unless someone closes it. | Continues under the current behavior. |
| Completed or cancelled | The record is already completed or cancelled. | The expiry rule leaves the record untouched. |

**Example:** R-82 was created nine days ago and entered **Awaiting customer documents** two days ago. If it is in scope, it has **five calendar days left** before expiry.

## Launch actions

- **Product** — Decide whether requests already open on launch day are in scope and communicate the decision to Support and Operations.
- **Support** — Explain how to submit a new return request when the portal shows **Expired**. Tell customers that the expired request stays closed.
- **Operations** — Use the date the request entered **Awaiting customer documents** to assess expiry timing. Apply Product’s launch-day scope decision when checking requests that were already open.
- **Communications** — Decide whether customers will also receive an expiry email. The portal will show **Expired** regardless of that decision.
