# Return request expiry — launch impact analysis

After launch, a return request in **Awaiting customer documents** expires after **seven calendar days in that status**. The clock starts when the request enters the status. Today, open return requests stay open indefinitely unless someone closes them.

**Launch-day decision for Product:** Decide whether the rule applies to requests already open at launch. Until Product confirms the scope, Support and Operations should treat expiry timing for those requests as provisional.

| Case | What changes | Team action |
|---|---|---|
| In-scope request in **Awaiting customer documents** | The request expires after seven calendar days in the status. | Operations uses the status entry date to determine when expiry is due. |
| Expired request | The portal shows **Expired**. The customer can submit a new request, and the expired request stays closed. | Support explains how to submit a new return request. |
| Request in **Internal review** | The request remains open under the current rules. | Support and Operations continue their current handling. |
| Completed or cancelled record | The record is unaffected. | No action required. |

**Example:** R-82 was created nine days ago and entered **Awaiting customer documents** two days ago. If Product includes it in the launch scope, it has **five calendar days left** before expiry.

**Open decision for Communications:** Decide whether to send an expiry email. Support can explain the **Expired** portal status and how to submit a new request while the email decision is pending.
