# Return request expiry at launch

After launch, return requests in **Awaiting customer documents** will expire after seven calendar days in that status. The clock starts when the request enters the status. Customers will see **Expired** in the portal and can submit a new request. The expired request stays closed.

**Product must decide whether the rule applies to requests already open on launch day.** Operations and Support need that decision before applying the seven-day rule to those requests. Communications also needs to decide whether customers will receive an expiry email.

| Case | Today | After launch | What teams need to do |
|---|---|---|---|
| In-scope request awaiting customer documents | Stays open indefinitely unless someone closes it. | Expires after seven calendar days in the status. | Operations uses the status entry date to determine when the request expires. |
| Request in **Awaiting customer documents** that is already open on launch day | Stays open indefinitely unless someone closes it. | Expiry depends on Product’s decision about launch-day scope. | Product confirms scope. Operations and Support use that decision when handling these requests. |
| Customer whose request expires | Open requests have no automatic expiry. | The portal shows **Expired**. The customer can submit a new request, and the expired request stays closed. | Support explains how to submit a new request. Communications decides whether to send an expiry email. |
| Request in **Internal review** | Stays open indefinitely unless someone closes it. | The expiry rule does not apply. | Operations continues handling it as today. |
| Completed or cancelled record | Already completed or cancelled. | The record is untouched. | No action required. |

**Example.** R-82 was created nine days ago and entered **Awaiting customer documents** two days ago. If R-82 is in scope, it has **five calendar days left** in that status before expiry.
