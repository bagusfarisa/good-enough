# Return request expiry — launch impact analysis

After launch, return requests in **Awaiting customer documents** will expire after seven calendar days in that status. **Product needs to decide whether the rule applies to requests already open on launch day.** That decision determines which existing requests Operations should expect to expire and when Support should tell those customers the deadline applies.

## What changes

| Case | Today | After launch | Impact |
|---|---|---|---|
| Awaiting customer documents | The request stays open indefinitely unless someone closes it. | An in-scope request expires after seven calendar days, counted from when it entered this status. | Operations should use the status-entry date to determine when a request expires. |
| Expired request | Time spent waiting for documents does not close the request. | The customer sees **Expired** in the portal. The expired request stays closed, and the customer can submit a new one. | Support should explain how to submit a new return request. |
| Internal review | The request stays open unless someone closes it. | The seven-day expiry rule does not apply. | No change to the review process. |
| Completed or cancelled | The record is already closed. | The rule leaves these records untouched. | No action required. |

**Example.** R-82 was created nine days ago and entered **Awaiting customer documents** two days ago. If it is in scope, it has **five calendar days left** in that status.

## Open launch decisions

- **Product · Existing requests.** Decide whether requests already open on launch day are in scope. Operations and Support need that answer to apply the rule to existing requests.
- **Communications · Expiry email.** Decide whether to send an expiry email. Support can explain the **Expired** portal status and how to submit a new request. Any guidance about email is pending this decision.
