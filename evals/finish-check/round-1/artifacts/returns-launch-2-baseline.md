# Returns expiry launch-day Support handoff

**Launch: May 12 at 09:00 UTC.** Before briefing the team, confirm Elena’s decision on requests already open at launch and check the launch tracker for Nia’s email decision. While Elena’s decision is pending, keep already-open requests out of the automation. Tell affected customers their current request stays open and they can upload documents there. Do not ask them to start over.

| Customer’s request | What Support should tell them |
| --- | --- |
| Already open at launch and Elena’s decision is pending | “Your current request is still open. You can upload your documents there.” |
| Opened after launch and awaiting documents | “You have seven calendar days from when your request entered **Awaiting customer documents**. If your documents arrive before the request expires, it continues as usual.” |
| Expired | “Your original request is closed. You can submit a new return request in the portal.” |

The automation checks hourly and applies only to requests in **Awaiting customer documents**. For requests opened after launch, the next hourly check after the seven-day threshold expires the request if it is still in that status. The portal displays **Expired** either way on email, and the original request stays closed.
