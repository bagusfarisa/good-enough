# Return request expiry — launch impact analysis

Today, return requests stay open until someone closes them. After launch, an in-scope request in **Awaiting customer documents** will expire after seven calendar days in that status. The clock starts when the request enters the status. The customer will see **Expired** in the portal and can submit a new request. The expired request stays closed.

## Impact by team

| Team | Launch impact |
| --- | --- |
| Support | Explain when the seven-day clock starts, what **Expired** means in the portal, and how to submit a new return request. Make clear that the original request stays closed. |
| Operations | Use the date the request entered **Awaiting customer documents** to determine when it expires. Requests in **Internal review** are unaffected, and completed and cancelled records stay as they are. |
| Product | Decide whether requests already open on launch day are subject to the rule. That decision determines whether those requests can expire under the new policy. |

## Timing example

**R-82** was created nine days ago and entered **Awaiting customer documents** two days ago. If it is in scope, it has **five calendar days left** in that status before it expires.

## Open launch decisions

| Owner | Decision | Impact |
| --- | --- | --- |
| Product | Does the rule apply to requests already open on launch day? | Support and Operations need the answer to determine which existing requests can expire. |
| Communications | Will customers receive an expiry email? | Support needs the answer to explain what notification customers can expect. The portal will show **Expired**. |
