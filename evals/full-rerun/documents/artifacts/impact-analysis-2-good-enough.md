# Return request expiry at launch

After launch, a return request that spends seven calendar days in **Awaiting customer documents** will expire. The clock starts when the request enters that status. Customers will see **Expired** in the portal and can submit a new request. The expired request stays closed.

**Launch-day decision:** Product still needs to decide whether the rule applies to requests already open on launch day. Support and Operations should use that decision to determine which existing requests will expire. Communications still needs to decide whether customers will receive an expiry email.

## Impact by request status

| Request status | Today | After launch | What teams need to do |
|---|---|---|---|
| Awaiting customer documents | Stays open indefinitely unless someone closes it. | In-scope requests expire after seven calendar days in this status. The portal shows **Expired**, and the customer can submit a new request. | Support should explain how to submit a new request. Operations should use the date the request entered the status to determine when it expires. |
| Internal review | Stays open indefinitely unless someone closes it. | Continues under the existing rules. | No expiry-related action. |
| Completed or cancelled | Records are already closed. | Records retain their existing status. | No expiry-related action. |
