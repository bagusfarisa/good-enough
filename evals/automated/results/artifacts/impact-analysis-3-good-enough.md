# Return request expiry — launch impact analysis

After launch, an in-scope return request expires after seven calendar days in **Awaiting customer documents**. The clock starts when the request enters that status. Today, all open return requests stay open indefinitely unless someone closes them.

| Request or event | After launch | Impact |
|---|---|---|
| Awaiting customer documents | The request expires after seven calendar days in that status. | Support and Operations should use the date the request entered the status to explain when it expires. |
| Expired request | The portal shows **Expired**. The customer can submit a new request, and the expired request stays closed. | Support needs to explain how to submit a new return request. |
| Internal review | The request remains open until someone closes it, as it does today. | Operations continues its current review process. |
| Completed or cancelled | Existing records stay as they are. | Operations has no action for these records. |

**Example.** R-82 was created nine days ago and entered **Awaiting customer documents** two days ago. If the rule applies to R-82, it has five calendar days left in that status.

## Open launch decisions

- **Product** needs to decide whether the expiry rule applies to requests already open on launch day. This determines whether Operations and Support should apply the seven-day rule to requests already awaiting documents at launch.
- **Communications** needs to decide whether to send an expiry email. The portal will show **Expired**.
